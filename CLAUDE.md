# NEONO: project guide for Claude

NEONO is a 3D, neon-styled online card game modeled on classic UNO, for 2–10 players. It runs live on free tiers of Vercel, Neon and Ably. This file covers the whole project: product decisions, architecture, code map, how each subsystem works, testing, deployment, and lessons learned. Read it before changing anything.

> **Also read `AGENTS.md`.** This project uses **Next.js 16.4**, which differs from older Next.js. When in doubt, check the bundled docs in `node_modules/next/dist/docs/`. Route params are async (`await ctx.params`, `await params`). `RouteContext<'/path'>` and `PageProps<'/path'>` are global type helpers, generated by `next dev`, `next build` or `npx next typegen`.

## 4. Architecture

```
Browser (Next.js client)                     Vercel route handlers (Node)            Neon Postgres
 ├─ R3F 3D scene + DOM HUD   ──POST──────►   /api/rooms/[code]/action ──load──►     rooms (state jsonb, version int)
 ├─ Zustand game store (versioned views)     │  engine.applyAction()  (pure TS)      ◄─ UPDATE … WHERE version=$v
 ├─ director: events → animations/sound      │  optimistic-lock save, retry ×4
 └─ realtime transport  ◄──── Ably ─────────  └─ Ably REST batchPublish: ONE private channel per player
        (dev: SSE from /api/dev/stream)              room:{code}:p:{playerId}  ← full public+private view + events
                                              chat/presence/reactions: room:{code}:chat (clients publish directly)
```

**The flow for every move:**
1. The client POSTs an action.
2. The server loads the row and runs the engine.
3. It saves with `UPDATE … WHERE version = v`.
4. On a conflict it reloads and retries.
5. It publishes a `GameMessage` to every human's private channel.
6. It returns the caller's message in the HTTP response too, so the caller doesn't wait for Ably.

- **Every message carries full views** (`{v, pub, priv, ev, now}`). Clients keep the highest `v` and ignore duplicates and out-of-order messages. A missed message is harmless, because the next full view corrects everything.
- **Hidden information.** The deck order and other players' hands never leave the server. `eventsFor()` strips drawn-card details from other players' events. Ably tokens can only subscribe to the player's own game channel (`room:X:p:<pid>`) plus publish/subscribe/presence on `room:X:chat`. Clients **cannot publish game moves**.
- **No server process for timers or bots.** State has a `deadline`: the AFK turn timer for humans, about 0.9–1.8s of pacing for bots and autopilot. It also has `roundEndsAt` for the round clock. `dueAt(state)` is the earlier of the two; when it passes, a client calls `POST /api/rooms/[code]/tick`. The **tick leader** (the connected human in the lowest seat, from presence) fires about 120ms after the deadline; everyone else is a backup at +1.8–2.7s. The server re-checks the deadline, applies a `timeout` action (bots decide in the engine), and ignores duplicates via optimistic locking.
- **Dev fallbacks.** With no `DATABASE_URL`, an in-memory store on `globalThis` is used. With no `ABLY_API_KEY`, an in-process bus streams over SSE (`/api/dev/stream`, chat via `/api/dev/chat`, presence tracked per connection). Production **requires** both (`transport()` and `getStore()` throw otherwise).

## 5. Rules engine (`src/engine`): pure, deterministic, fully tested

The entry point is `applyAction(prev, action, actorId, now, rng) → { state, events }` in `reducer.ts`. It `structuredClone`s the state and mutates the clone. Illegal moves throw `RuleError(message)`, which the server maps to HTTP 400 and the client shows as a toast.

### State (`types.ts`)

- `GameState` holds the following:
  - `phase` (`lobby | playing | round_over | game_over`), `round`, `hostId` and `settings`
  - `players[]` (seat order)
  - `drawPile` and `discardPile` (top = **last** element)
  - `currentColor`, `direction` (±1), `turnIndex`, `dealerIndex`
  - `turn`, `drawStack`, `stackTopValue`
  - `unoWindow`, `deadline` (turn), `turnStartedAt`, `roundEndsAt` (round clock, null when off)
  - `totalCards`, `nextCardId`, `lastRound` and `gameWinnerId`
- `TurnState` is one of:
  - `play`
  - `drawn{cardId}` (you may play the drawn card or pass)
  - `stack{challenge|null}` (a draw penalty is pending: stack it, take it, or challenge a fresh Wild +4). **Only exists when the player can answer**: if they hold nothing stackable and there's no challenge, `drawEffect` calls `takePenalty` straight away.
  - `choose_color{purpose: roulette}` (the start card is never a wild any more)
- `PlayerState`: `status` is `active | out | left`, plus `saidUno`, `afkStrikes`, `autopilot`, `isBot`, `takenOver` (a bot is playing a human's seat), `offline` (taken over because they dropped off), `kicked` (taken over by a kick: no reclaim) and `partnerId` (team play). Players who leave mid-round stay in the array as `left` until the next round, so seat indices stay stable.
- `GameState` also has `spectators?: {id,name,avatar}[]` and `invites?: {from,to}[]`; both are optional so old saved rooms load (read with `?? []`).
- **Actions:**
  - In-game: `play`, `jump_in`, `draw`, `pass`, `take_penalty`, `challenge`, `choose_color`, `call_uno`, `catch_uno`, `timeout`
  - System: `offline {playerId}` (sent by the server after a presence check, like `timeout`)
  - Lobby/host: `join`, `update_settings`, `add_bot`, `remove_bot`, `kick`, `leave`, `transfer_host`, `start`, `next_round`, `back_to_lobby`, `close_room`
  - Teams (lobby / game over, team play on): `team_invite {playerId}`, `team_accept {playerId}`, `team_decline {playerId}`, `team_leave`

### Classic rules as implemented

- **Matching:** same color, same symbol, or any wild.
- **Starting card: always a number card.** If the flipped card is anything else (action, wild, extra), it goes back into the draw pile at random and the next number card from the top is used (user request; the old official start-card effects are gone). The player after the dealer starts.
- **Discard All for everyone:** with `cards.discardAll` on, after the deal each player without one swaps a random card of theirs for a random Discard All from the draw pile (seeded rng, card count unchanged). If the draw pile has none left (decks forced down at a big table), a new one is minted (`nextCardId`, `totalCards += 1`), so every player always gets one.
- **Drawing:** draw 1 (allowed even if you have a playable card). If the drawn card is playable you're in the `drawn` state and may play it or pass. If not, your turn ends. Drawing a penalty ends your turn.
- **Wild +4 challenge (default mode):** the victim gets a `stack` turn with `challenge` info. If the offender was guilty (held a card of the previous color), they draw 4 and the challenger plays normally. If innocent, the challenger draws 6 and is skipped.
- **Two players:** Reverse acts as Skip. **Reshuffle:** the discard pile (minus its top card) goes back into the draw pile when it runs out.
- **Going out on a draw card:** the next player still draws, which counts for scoring.
- **Scoring:** number cards = face value, action cards = 20, wilds = 50. Either single round or points mode with a target score.

### Optional switches and where they live

- `stacking`: `off | same | mixed | higher` (default `higher`; the lobby toggle turns it on as `higher`). Handled in `effects/draw.ts` and `legal.canStack`. Stacking ignores color. Wild Reverse +4 flips direction and can send a stack back. A victim who can't stack or challenge auto-takes the stack.
- `sevenSwap` / `zeroRotate`: `effects/numbers.ts`. A player who *receives* a 1-card hand is auto-marked as shouted. Mercy is checked after a swap.
- `jumpIn`: identical color and symbol, out of turn, only while there's no pending penalty. The turn continues from the jumper.
- `drawUntilPlayable` / `forcePlayDrawn`: `reducer.draw` and the `pass` guard.
- `wild4Mode`: `challenge` (default) / `free` / `restricted`.
- `cards.*`: wildReverse4, discardAll (also discards the player's other same-color cards; the played card stays on top), skipAll (same player goes again), draw4Color, wild6, wild10, roulette (the victim names a color and flips until it appears).
- `mercyRule` + `mercyLimit`: a player reaching the limit is `out`, and their cards go under the draw pile.
- `unoPenalty`; `afkAutopilot` + `afkThreshold` (a bot plays for an idle human until they act again).
- `teamPlay` (basic): see "Teams" below.
- `roundTimerMin` (basic): `startRound` sets `roundEndsAt`. `round.timeUp` / `endRoundOnTime` run at the start of every action in `dispatch`: once time is up the round ends (`time_up` event, `lastRound.timeUp`) and in-round moves are dropped, not rejected. `scheduleDeadline` halves deadlines inside `FINAL_STRETCH_MS` (60s). `mergeSettings` fills keys missing from old saved rooms from `CLASSIC_SETTINGS`.

### Offline takeover, reclaim and spectators

- `offline {playerId}` (system): a spectator is removed; in the lobby the player is removed (host passes on); otherwise the seat is **taken over** (`isBot`, `takenOver`, `offline`, reschedule if it's their turn, `player_offline` event, host passes to a human). Bots and unknown ids throw "Nothing to do", which the server reports as not applied.
- **Reclaim:** any in-round action from a `takenOver` actor gives the seat back first; `join` as the same id does too. `kicked` seats can't be reclaimed ("The host removed you from this game"). `start` / `back_to_lobby` drop `takenOver` seats, so a restart excludes offline players.
- **Spectators:** `join` mid-round, at a full table, or during a team game's `round_over` adds you to `spectators` (cap 20, `spectator_joined`). A spectator's `join` when a seat is allowed moves them into `players` ("Take a seat"). Spectators may only `leave`.
- `privateView` for a spectator: `spectator: true`, no hand, and `peek` with every active hand. `eventsFor(events, pid, revealAll)` leaves draws unredacted for them.

### Teams

- Partners are a `partnerId` pair. Invites live in `state.invites`; accepting pairs both and clears every invite involving either; inviting a bot, or someone who already invited you, pairs at once. Leaving, kicking, removing a bot or turning team play off unpairs.
- `start` runs `arrangeTeams`: needs an even count 4–10 ("Team play needs an even number of players…"), shuffles and pairs the unpaired, then seats `[T0a, T1a, …, T0b, T1b, …]` so partners sit opposite.
- Winning: going out wins for your team. `endRound` scores the other teams' hands and **both partners get the points**. `settle` ends the round when one team is left. Time-up compares team hand totals (ties: fewer cards, then turn order).
- A team player's `peek` holds their partner's hand while playing. `catchableTarget` never targets your partner. Bots don't aim draws/skips/reverses at their partner (−15) and swap with a rival.
- In a team game, leaving during `round_over` keeps the seat as a takeover (pairs must stay intact) and joiners spectate until the lobby.

### The shout window (designed for online play)

When a player goes down to 1 card without shouting, `unoWindow = {playerId, openedAt}`. For the first 1.2s nobody can catch them. After that anyone can, until 6.5s have passed. **Other players' moves don't close the window.** The original official rule ("before the next player acts") made catching impossible, because bots act within about a second. The window closes when the player shouts, draws, or time runs out (`expireUnoWindow` runs at the start of every action). You can also shout early while holding 2 cards on your own turn.

### Engine invariants (enforced by `fuzz.test.ts`)

- Total card count never changes.
- Card ids are unique.
- During play, the current player is active, at least 2 players are active (at least 2 teams in team play), and a deadline exists.
- Non-active players have empty hands.
- Bots never make illegal moves (`engineDebug.strictBots`).

Very long "marathon" games (huge hands, no mercy rule) are legitimate, so up to 1% of games may hit the step cap.

## 8. 3D scene (`src/scene`)

- **`GameCanvas.tsx`** mounts in the **lobby as well** as in game, so the deal animation plays from the first frame. It contains:

  - `discardSlot`: older cards lie scattered; the **top card is propped up** and tilted toward the camera, lifted so its near edge clears the felt.
  - `PLAYABLE_LIFT = 0.17`: how far playable cards rise on your turn (`handTopPx` budgets for it).

- **`cards/`**:
  - `cardTextures.ts` draws every face in **Canvas 2D** (original art; color-blind shape icons in the corners). Glyphs and corner indices get an ink outline via `outlined()` (a silhouette stamped in a circle, works for text and shapes). No glow/emissive maps. `faceTextures(card, tint)` caches per face **and per wild tint**. The font family comes from the `--font-unbounded` CSS variable, because next/font generates the family name. `refreshTexturesWhenFontsReady` redraws once the font loads.
  - `cardGeometry.ts`: a rounded card with three material groups (front, back, edge), 12 segments per corner. **Materials are matte `MeshStandardMaterial`; no clearcoat, no emissive**, because of the glare complaint. The edge is a warm grey (`#e4dac8`), a shade darker than the white border, so outlines and deck layers read. `cardMaterials(card, tint)`; `cardFaceGeometry()` is the rounded outline for overlays (the unplayable shade).

    - Each actor eases toward its zone's target every frame (`maath` damping).
    - Adds an arc and a roll while travelling.

## 10. Audio (`src/audio/sound.ts`)

- Everything is **synthesized with Web Audio**: sound effects plus a generative synthwave loop. There are no audio files, except optional voice clips.
- **The engine lives on `globalThis.__neonoAudio`** (context, buses, music timer, clips, preferences). That stops hot reload from creating a second, unstoppable music loop: the music toggle bug was exactly this.
- Turning music off fades out the current music bus and swaps in a fresh one, so notes already scheduled die with it.
- `unlockAudio()` must run on a user gesture. **Capture-phase `pointerdown`/`touchend`/`keydown` listeners call it on any interaction** (and `visibilitychange` resumes the context), so players who reloaded still hear other people's shouts. It also primes speech synthesis with a silent utterance (iOS won't speak later otherwise).
- `playVoice(name, delayMs?)` plays `/sfx/<name>.mp3` (clips are committed in `public/sfx/`), otherwise browser speech. Clips go through a **voice queue** (`E.voiceFreeAt`) so callouts never overlap; a clip that would wait more than 2.5s is dropped. `VOICE_LINES` lists them: `uno`, `caught`, one per action/wild card kind (`skip`, `reverse`, `draw2`, `draw4`, `wild`, `wild4`, `wild_reverse4`, `wild6`, `wild10`, `skip_all`, `discard_all`, `wild_roulette`), `swap` (7 rule), `rotate` (0 rule) and `draw` ("Draw cards!"). `speak()` only cancels when busy and then waits 60ms (Chrome drops an utterance queued in the same tick as `cancel()`).
- Director hooks (`director.ts`): a `play` event says the card's clip at landing time (number cards are silent); `swap`/`rotate` events say theirs; a `draw` event with reason `penalty`/`challenge`, or a `roulette`, says "Draw cards!" 650ms later for the victim.
- **Unplayable draw:** `draw()` in `reducer.ts` already ends the turn when the drawn card can't be played (the `drawn` state only exists for a playable card). The director shows a "NO PLAY" seat label (and a toast for you) so the automatic pass is visible.
- UI/fun sounds (`playSfx`): `next` (up next chime), `baton`, `emote`, `whoosh`, `splat`, `pop`, `boom`, `clink`, `smooch`.
- Card sounds: `cardSlap()` (air swish, cardstock snap, soft table knock; no pitched tones) for play/action/wild, with a triangle accent on action and an arpeggio on wild.

## 12. Deployment details (`scripts/deploy.mjs`)

**Steps:**
1. Check the Vercel and Neon logins.
2. Neon org: the first one, or `NEON_ORG_ID`. **neonctl prompts for an org without `--org-id`, and that prompt hung the first run.**
3. Reuse or create the Neon project `neono`. The region defaults to Singapore, or set `NEON_REGION`.
4. Get the pooled connection string, never printed.
5. Run `vercel link --yes --project neono`.
6. Set `vercel.json` regions to match Neon (the `REGIONS` map, e.g. Singapore → `sin1`).
7. Store each env var with `vercel env add NAME production --sensitive --force`, value on stdin, skipping existing ones unless `--reset-env`.
8. Run `vercel deploy --prod --yes`, which shows the build log, and print the **Aliased** public URL.

**Script details:**
- All CLI calls run with `stdin: "ignore"`, so an unexpected prompt fails fast instead of hanging.
- The script loads `.env.local` (dotenv), which is where `ABLY_API_KEY` comes from.

**Free-tier limits:** Ably Free allows 6M messages a month and 200 concurrent connections, about 20 full tables at once. Neon Free has 0.5 GB of storage and 100 CU-hours, and scales to zero after 5 minutes, so the first move after an idle spell takes about a second. Vercel Hobby is free for non-commercial use, and daily crons are allowed.

## 13. Gotchas and lessons learned

- **Windows tooling:** shell heredocs containing apostrophes or backticks broke the Bash tool. Write edit scripts to the scratchpad and run them with `python`, or use the Write and Edit tools.
- **vitest 5 / rolldown** needs `@rolldown/binding-win32-x64-msvc`. It's listed under **optionalDependencies**, so Linux and Vercel installs don't fail. `vitest.config.mts` (ESM) uses `import.meta.dirname`.
- **ESLint:** `react-hooks/immutability` and `react-hooks/purity` are turned off **only for `src/scene/**`**, because R3F mutates three.js objects in `useFrame` by design. Elsewhere, avoid synchronous `setState` in effects; derive values instead (see `useRoom` and `Scoreboard`).
- **R3F:** `useFrame` with a positive priority disables automatic rendering, so the camera uses -1. Keep keyed lists in one array; separate `.map`s remount objects that move between them.
- **Card glare** came from clearcoat plus environment reflections on hand cards facing the camera. Keep the materials matte.
- **Seat labels overlapping:** fixed with arc-length spacing. Pile cards being too small was fixed with `PILE_SCALE`. The propped-up top card sank into the table until it was lifted by `sin(tilt)` × half its height.
- **Next 16:** `cacheComponents` and `partialPrefetching` were removed from the scaffolded `next.config.ts` to keep the app simple and fully dynamic.
- **Vercel:** per-deployment URLs require a login (deployment protection); the alias is public.
- **Whole-screen flashing on phones (High quality).** A first fix (near plane, y-offsets, SMAA on touch) wasn't enough. The rules now, which must be kept:
  - **No `EffectComposer`/post-processing.** Its half-float targets are reallocated on every resize and are unreliable on mobile GPUs. Use the renderer's own MSAA.
  - **No `backdrop-filter` anywhere** (it was on a full-screen lobby overlay, `.glass` panels and pills). Android Chrome recomposites blur over an always-redrawing WebGL canvas and flashes.
  - **Auto quality only steps down**, and the pixel ratio only changes with the tier: every change resizes the canvas.
  - camera `near = 1.2`; felt at y=0.012; deck, pile and fans at y≥0.032; debounced canvas resizes, for the mobile address bar.
- **Tailwind v4 layering:** unlayered CSS beats `@layer utilities`, so custom component classes must live in `@layer components`, or utilities like `bg-*`, `py-*`, `fixed` silently lose.
- **Bright background:** additive blending and `toneMapped={false}` colors > 1 wash out to white. Use normal blending and plain palette colors.

## 15. Leaving and closing rooms

- **Leave in the lobby / between rounds:** the player is removed. **Leave mid-game:** `removePlayer` in `reducer.ts` turns the seat into a bot (`isBot = true`, `takenOver = true`), keeps the hand, and schedules a bot deadline if it's their turn. Rejoining through the link (`join` as the same id) gives the seat back. `back_to_lobby` and a fresh `start` drop `takenOver` bots.
- **Offline:** see §5 and §7. A dropped player's seat is taken over within ~3s (lobby: removed); they reclaim it by reopening the link. A restart (`start`, `back_to_lobby`) drops takeover seats, so offline players are excluded.
- **Kick mid-game:** like leave, but the seat is marked `kicked` and can't be reclaimed.
- **Host leaves:** the host role passes to the next human (bots, including takeover bots, are skipped).
- **Close room:** host-only `close_room` action → `room_closed` event (everyone gets a toast and goes home) → `perform` in `room-service.ts` deletes the row (`store.remove`). The room is also deleted when the last human leaves or is kicked (`leave`/`kick` with no human left).
- UI: lobby has "Leave room" and (host) "Close room"; the in-game settings sheet has the same two. Close asks for confirmation.
